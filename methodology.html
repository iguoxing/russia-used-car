00 · 一页结论：这套方法到底在做什么

本质不是「找通讯录」，而是把一份海关提单统计名单反向还原成可核验的法人主体 + 决策人 + 合规触达路径。查找动作只占三成，剩下七成是主体确权、同名消歧与剔除假买家。

一句话方法：不要在海量的「找人网站」里逐个撞运气，先用免费官方登记册把公司主体钉死（ИНН / ОГРН / 全称 / 状态），再用主键拼 URL 批量取法定代表人，然后用官网深页、品牌总部职能邮箱、集团层穿透、中国侧供应链反查四条线补触达路径，最后用证据等级 + 来源 URL 把每条线索标成已验证 / 候选 / 剔除。

常见做法（低效）本次做法为什么
拿公司俄文名去搜索引擎搜「联系人」先补齐 ИНН / ОГРН，用主键拼 URL 进工商档案俄企同名极多；«ВОСТОК АВТО»、«АТЛАНТ»、«ВОЛГА» 都踩过同名陷阱，纯名称检索必然串号
用 Rusprofile / EGRUL 等「知名库」实测逐个站点，换成 СБИС 按 ИНН 直连 + 官方 МСП POST 接口前者验证码 / 403 / 按国家封锁；后两者免费免登录、可批量、稳定 200
盯着 1–2 人的小微进口主体找电话集团 / 品牌总部穿透，找 dnd@ 经销商网络发展部、采购平台2022–2025 新设小微主体公开足迹趋近于零；一条总部入口覆盖的交易量远大于逐个找电话
在俄罗斯找俄罗斯人在中国找他们的中国供应商 / 中国品牌方国际业务部提单伙伴、企查查、中文电话与微信可绕开俄语冷启动，还能拿到同行引荐
把打码值「猜」成完整号码只在位数与首尾字符完全吻合时才还原，否则留白本批 15 个打码值逐条核对，v6 还原 0 条 —— 不脑补才不会打错人
查到什么就写进表L1–L4 分级 + 每条附来源 URL + 候选打标销售拿到「已验证」与「未验证·候选」混在一起的表，比没有表更危险

最终客观上限（很重要）：100 家里约 26–38 家本就不该找（报关行 ПО ПОРУЧЕНИЮ 代理申报、物流终端、轮胎配件、名单串行错误、已注销、非俄主体）。有效客户里 65 家「具名 + 有路径」（v4 严口径，约 88%）；剩余 9 家是 2022–2025 新设 1–2 人主体、同名无法确认或自然人隐私，公开网络确实不存在联系方式 —— 继续加渠道的边际收益接近 0，需要用户自己的付费库 / 人工 EGRUL 摘录 / 客户补 ИНН。

口径提醒：「具名决策人 92 家」与「可直接触达 29 家」不矛盾：前者是工商法代姓名（可具名但未必有联系方式），后者是已验证完整电话或邮箱。中间层是「有总机 / 职能邮箱 / 集团层路径 / 引荐路径」。

03 · 六轮演进：每一轮换掉的错误假设

六轮不是简单「多找几遍」，而是每次遇到天花板就换掉一个错误假设，因此每一轮的净产出都不一样。成果表 v1–v6 全部保留，不覆盖旧版。

04 · 武器库：12 类通道逐条拆解

每条给出「入口 / 检索式 / 拿到什么 / 实证 / 坑」。标 核心 的是下次拿到新名单应第一批跑的；标 辅助 的用于补齐与交叉验证。
A1СБИС / SabyProfile 按 ИНН 直连工商档案 核心
入口
https://sbis.ru/contragents/<ИНН>（自动跳 saby.ru/profile/<ИНН>-<КПП>）
拿到什么
法定代表人全名 + 任职起始日、在营/注销、ОКВЭД、股东与实控人、打码电话/邮箱、官网、营收、风险信号
实证
64 家合法 ИНН 64/64 抓到，61 家具名负责人，3 家查出已注销；40 家拿到邮箱域名、28 家打码电话
坑
必须直连：显式挂本地 Clash 127.0.0.1:7897 全部 000 超时，直连 200；按名称搜索 / 按电话邮箱反查属付费功能，免费页只返回营销落地页
A2俄官方 Единый реестр МСП 的 POST 接口 核心
POST https://rmsp.nalog.ru/search-proc.json
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest
mode=quick&query=<ИНН 或 俄文全称>&page=1&sortField=NAME_EX&sort=ASC
拿到什么
inn / ogrn / name_ex / is_active / okved1 / okved1name / regioncode / cityname / dtregistry —— 官方一手、免登录免付费、稳定 200
实证
85 家按 ИНН 命中、零错误；15 家按名称精筛；补齐全称截断的 #60 «ЭКОМТЕХ»、确认 #11 候选 ИНН
坑
按名称查询固定只返前 10 条（page / pageSize 无效），同名数千时无法穷举；is_active=0 多为退出中小企业名录，不等于工商注销；大企业 rowCount=0 属正常
A3★ 组合技：官方册拿 ОГРН → 拼 org-info URL 核心·最高产
做法
A2 拿到 ogrn → https://www.org-info.com/company/<ОГРН>，或搜索引擎用 site:org-info.com/company "<公司名>" "<ИНН>" 叠加检索
实证

纯 ИНН 单独搜会被搜索引擎当普通数字，必须叠加公司名；用 ОГРН 拼 URL 最稳。邮箱/电话是工商登记留存值，时效需复核（#73 УЛЕЙ 的 СБИС 与 readyratios 负责人不一致）
A4官网深页：/about/team、/partneram、/contacts、/dealerships 核心

09 · 工程流水线：脚本、代理、表结构

每一轮的标准动作

  1. 读源表：本地 Office 编辑通道 sheet_get_cell_data 导出 100 行 × 30 列为 CSV / JSON（/tmp/russia_top100.json）。
  2. 批量抓取：Python 脚本按 ИНН 拼 URL（/tmp/saby_batch.py），正则解析负责人 / 状态 / ОКВЭД / 股东 / 打码邮箱电话；官方册脚本 /tmp/rmsp_official.py 做 100 家核验。
  3. 网页取证：curl / 网页抓取通道取 HTML，解析 mailto:、tel:、JSON-LD、state-view 地图 JSON；失败状态（403 / 000 / 502）如实记录，不猜。
  4. 版本化建表：.俄罗斯TOP100客户_决策人核验vN.ref/build_vN.py（openpyxl）生成新表，旧版一律保留不覆盖；冻结表头、加筛选、颜色分级、超链接、数据校验与批注；写入 AIGC 标识。
  5. 校验与交付：重开文件核对 sheet 数、行数、链接数、等级高亮；用文件预览打开成品。

环境与踩坑

  • 网络：网络中断 / 502 / ENETUNREACH / stream timeout 时改为直连网页抓取或等待网络恢复后重试；子代理常只返回摘要，需明确要求输出完整表格。
  • 代理：显式 127.0.0.1:7897（Clash）导致全量超时；系统自带代理可用；抓 СБИС 以直连最稳。
  • 抓取边界：`curl -sS --compressed --max-time 35 -A "Mozilla/5.0"`，POST 接口需带 X-Requested-With: XMLHttpRequest 与正确 Content-Type。
  • 建表常见错误（均已修复）：SOP 标题错位、DataValidation / Comment 落在分组行、make_sheet(...) 参数不匹配、等级标签滞后导致颜色误导、总览行号错误、冗余循环、real(v) 空值处理。
